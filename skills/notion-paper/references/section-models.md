# 章节处理与写作模型

## 基本原则

把章节内的小标题视为需要回答的问题。以用户的阅读记录为主体，用 PDF 核对事实、回答即时疑问和补充明确要求的公式；不要把章节处理变成逐段翻译或自动代写。

## 内容分类

### 用户笔记

保留用户关注的因果关系、技术判断、实验怀疑和个人启发。可压缩、重组和修正表达，但不要把个人判断伪装成论文结论。

### 即时疑问

在保留问题区以外，识别：

- “这里需要你解答”
- “这里不理解/不太清楚”
- “为什么……”
- “是否……”
- “这里是什么意思”
- “需要确认……”
- 其他明显写给协作者的阅读中问题

在对话中回答。决定是否将答案转化为正文：

- 若答案是理解当前章节不可缺少的确定事实，将其压缩成普通陈述融入润色稿。
- 若只是消除临时困惑，从润色稿删除问题，不写入问答。
- 若答案依赖额外假设或证据不足，不写成确定事实。

每项决定都在运行报告中说明。

### 保留问题

以下标题或明显同义标题下的内容是后续阅读导航：

- 后文需要验证的问题
- 疑问
- 实验问题
- 未解决的问题
- 待验证问题
- 读完未解决的疑问

不要回答。只润色措辞、合并重复问题、整理逻辑和编号。

### 公式要求

当用户写“这里需要补公式”等要求时：

1. 从 PDF 找到对应公式。
2. 使用规范 LaTeX 写入润色稿。
3. 说明变量、计算目的、输出含义以及它回答的问题。
4. 不补推导过程。
5. 删除原操作提示。
6. 公式无法唯一确认时，不猜测写入。

### 子页面要求

只有明确出现“单独开子页面”“新建子页介绍”等要求时才创建。子页用于额外知识、长推导、跨章节背景或可复用解释；直接写成正式内容，不经过润色稿/commit 生命周期。

## 通用润色规则

- 对整页润色，包括末尾保留问题。
- 合并重复内容，拆分过长句子，显式写出因果关系。
- 保留必要英文术语、方法名和变量。
- 保留用户的“我的理解”“启发”“我认为”“需要审查”。
- 使用“论文声称”“实验显示”“代码表明”“我的判断”等边界词。
- 不把 proxy 与最终安全目标直接等同。
- 不把 FLOPs、参数比例等代理量直接等同于端到端成本。
- 不删除图片、表格、公式、链接或 page mention；可移动到更合适的位置。
- 不为追求完整而补写用户尚未阅读的内容。发现缺口时在对话中提示。

## 各章节需要回答的问题

### Abstract

- 论文研究什么问题？
- 现有方案的核心缺陷是什么？
- 核心思路是什么？
- 方法由哪些模块组成？
- 论文报告的关键结果是什么？
- 本节留下哪些后续问题？

### Introduction

- 为什么问题重要？
- 真实矛盾和 Research Gap 是什么？
- 已有路线为什么不足？
- 核心 insight 是什么？
- 主要贡献是什么？
- 后文需要验证哪些 claim？

### Background and Threat Model

- 系统与攻击背景是什么？
- 安全目标与评价指标是什么？
- 攻击者能做什么、知道什么、不能做什么？
- 哪些组件和信息属于保护对象？
- 哪些攻击或失效不在范围内？
- 论文结论依赖哪些可信假设？

### System Overview

- 输入和输出是什么？
- 端到端流程是什么？
- 每个步骤解决哪个安全或性能问题？
- 各模块之间的因果关系是什么？
- 与相邻方案的本质区别是什么？
- 后文需要验证哪些模块假设？

### Technology / 方法页

- 模块解决哪个子问题？
- 直接或穷举方法是什么，为什么不可行？
- 核心假设或低成本 proxy 是什么？
- 公式各项表示什么？
- 算法、选择或优化流程是什么？
- 直接优化什么，没有直接优化什么？
- 实验验证的是单项因果、排序、排序前缀，还是整体集合？
- 用户的理解和怀疑是什么？

### Implementation

- 离线与在线阶段分别做什么？
- 使用哪些模型、攻击、系统组件和硬件？
- 关键参数和实现假设是什么？
- 论文、Artifact 和代码是否一致？

### Evaluation

- 实验要回答哪些 claim？
- baseline、模型、数据集、攻击者和 query budget 如何设置？
- 安全、效用和真实性能指标分别是什么？
- 结果是否直接支撑 claim？
- 是否存在模型容量、攻击链耦合、代理指标或比较公平性问题？
- FLOPs、参数量与端到端延迟之间有什么差异？

### Discussion

- 安全保证的边界是什么？
- 支持哪些模型、攻击和硬件？
- 哪些结论依赖超参数或部署假设？
- 可扩展性与 future work 是什么？

### Related Work

- 相邻工作分别采用什么问题抽象和保护路线？
- 当前论文改变了哪个设计维度？
- 哪些技术可以组合，哪些目标不同？
- 不要只罗列论文名称。
