# 阅读笔记写作风格

## 成品定位

成品是“按自己的研究问题重组后的阅读笔记”，不是论文摘要、章节翻译、百科条目或相关工作综述。用户决定关注什么；协作者负责把这些关注点压缩成清晰、可核对、可继续追问的结构。

优先级从高到低：

1. 保留用户的研究问题、归类方式和判断。
2. 保证事实、公式和证据边界准确。
3. 压缩重复与口语化表达。
4. 最后才考虑形式完整。形式完整不得反过来驱动补写。

## 生成顺序

### 1. 建立内容账本

在内部逐块标记，不写入 Notion：

- `论文事实`：PDF 明确陈述的设计、假设或结论。
- `实验事实`：图表和实验直接显示的结果。
- `代码/Artifact 事实`：实现与论文相同或不同之处。
- `用户判断`：我的理解、怀疑、启发、比较和批评。
- `即时疑问`：需要在对话中回答的问题。
- `保留问题`：章末留给后文验证的问题。
- `操作请求`：补公式、建子页、移动媒体等。

同一句包含多个类别时拆开。不能确定来源的内容不得改写为论文事实。

### 2. 重建问题骨架

先回答“用户在这一页试图弄清楚哪几个问题”，再生成标题。优先沿用原有标题；允许合并重复标题、把宽泛标题改得更准确，但不得自动套用章节检查表。

典型骨架仅供判断，不是固定模板：

- 摘要：问题 → 现有缺陷 → 核心转向 → 关键结果 → 疑问。
- 引言：防护目标/真实矛盾 → Research Gap → 核心 Insight → 贡献 → 后文验证。
- 背景与威胁模型：系统背景 → 安全目标 → 攻击者能力 → 保护对象与边界。
- 技术页：子问题 → 直接方法为何不可行 → 核心假设或 proxy → 公式含义 → 流程 → 我的理解/局限 → 后文验证。
- 实验页：claim → 设置 → 结果 → 结果能证明什么 → 耦合、代理量或公平性问题。

只选择当前笔记真实包含的部分。没有内容支撑的标题不生成。

### 3. 压缩成文

- 每个小节首句直接给结论或定义，不用“本文首先”“本节主要介绍”等预告句。
- 后续句子只承担定义、因果、对比、证据或边界中的一种作用。
- 连续步骤、能力集合、输入输出和并列比较使用列表；一个完整判断使用短段落。
- 保留必要英文术语，中文能够准确表达时不要堆叠同义英文。
- 公式之后说明“各项是什么、计算什么、输出如何使用”，不复述推导。
- 使用 `###` 作为正文主标题，并延续现有页面的橙色标题样式；技术页内部确需分层时再用 `####`。
- `# 润色稿（待确认）` 只作为草稿包装标题，不属于正文结构。

## 信息增量边界

润色默认是压缩任务，不是扩写任务。只有以下内容可以增加：

1. 回答即时疑问所必需、且应融入正文的确定事实。
2. 用户明确要求补充的公式及变量含义。
3. 用户明确要求创建的知识子页内容。
4. 修正原笔记事实错误所需的最小解释。

即使允许增加，也只增加能改变当前章节理解的内容。不要因一次外部搜索顺带加入完整研究史、作者履历、所有攻击变体或与论文无关的定义。

正文完成后检查：除上述允许项外，润色稿的语义范围不应大于原笔记；表达长度通常应更短。如果明显变长，逐段删除没有参与当前因果链或判断的内容。

## 研究笔记语气

- 直接陈述，不写宣传式概括和空泛评价。
- 对论文使用“论文提出/假设/声称”；对结果使用“实验显示”；对实现使用“代码/Artifact 表明”；对用户观点保留“我的理解/我的判断/这里需要审查”。
- 允许明确批评，但必须指出批评落在哪个推理跳步，例如 `proxy ≠ 目标`、`相关性 ≠ 干预收益`、`前缀集合有效 ≠ 排序中每项都关键`。
- 不把用户的探索性语言抹平成权威口吻，也不替用户制造新的“启发”。

## 章节密度

- Abstract 应高度压缩，通常 4–6 个小标题，每个小标题 1 个短段落或一个短列表。
- Introduction 可以展开因果链，但每个小节只服务一个问题。
- Background and Threat Model 追求可扫描性；攻击者能力、不可访问内容和安全边界用列表明确分开。
- Technology 页面允许更长，但必须围绕一个技术子问题，公式与流程后要回到“它实际优化/证明了什么”。
- Evaluation 按 claim 和证据组织，不按 Figure 顺序逐图复述。
- 知识子页默认以“与当前论文的关系”为边界，通常不逐篇文献展开。

## 强制质量门槛

出现任一情况都先重写，不得写入 Notion：

- 把章节检查表的每个问题都变成标题。
- 按 PDF 段落或论文目录顺序复述，而没有体现用户自己的归类。
- 用“本文主要”“该方法旨在”“首先/其次/最后”填充没有信息量的过渡。
- 把简短线索扩成百科式综述或按作者逐篇罗列文献。
- 新增内容无法回答“它改变了当前章节的哪个判断”。
- 把论文声称、外部资料或用户判断混为同一事实层级。
- 把 proxy、FLOPs、参数量、排序分数等直接写成最终安全或性能结论。
- 删除或回答了保留问题区的问题。
- 大段连续散文掩盖了攻击者能力、步骤、输入输出或对比关系。
- 子页没有回到它与当前论文的关系。

## 写入前自检

1. 用一句话概括当前页真正要解决的问题；无法概括时先重组。
2. 检查每个标题是否能被正文直接回答。
3. 检查每段新增内容是否来自允许的信息增量。
4. 检查事实层级和用户判断是否有边界词。
5. 检查保留问题是否原样保留其开放性。
6. 删除所有操作提示、即时问答痕迹和不服务于当前判断的外部背景。
7. 对照 [examples.md](examples.md) 的合格/不合格示例；未通过则不写入。
